# Интерфейс инструментов — зачем агентам нужен структурированный I/O

> Языковая модель производит токены. Программа выполняет действия. Промежуток между ними закрывает интерфейс инструментов: контракт, который позволяет модели запросить действие, а host-среде выполнить его. Каждый стек 2026 года — function calling в OpenAI, Anthropic и Gemini; `tools/call` в MCP; task parts в A2A — это разная кодировка одного и того же четырехшагового цикла. Этот урок дает имя циклу и показывает минимальный механизм для его запуска.

**Тип:** теория
**Языки:** Python (stdlib, без LLM)
**Предварительные знания:** Phase 11 (API LLM completions)
**Время:** ~45 минут

## Цели обучения

- Объяснить, почему LLM, которая умеет только генерировать текст, сама по себе не может выполнять действия в реальном мире.
- Нарисовать четырехшаговый цикл вызова инструмента (describe → decide → execute → observe) и назвать, кто отвечает за каждый шаг.
- Описать инструмент как три части: имя, вход JSON Schema и детерминированная executor-функция.
- Различать pure-инструменты и инструменты с побочными эффектами и объяснять, почему это разделение важно для безопасности.

## Проблема

LLM выдает распределение вероятностей по следующему токену. Это вся поверхность вывода. Если спросить чат-модель "какая сейчас погода в Бангалоре", она может написать правдоподобное предложение, но не может сама обратиться к weather API. Предложение может случайно оказаться верным или быть устаревшим на три дня.

Интерфейс инструментов нужен именно для закрытия этого разрыва. Host-программа — ваш agent runtime, Claude Desktop, ChatGPT, Cursor или кастомный скрипт — объявляет модели список вызываемых инструментов. Когда модель решает, что нужно действие, она выдает структурированный payload с именем инструмента и его аргументами. Host парсит payload, реально запускает инструмент и возвращает результат обратно. Цикл продолжается, пока модель не решит, что новые вызовы больше не нужны.

Первая версия этого контракта вышла в июне 2023 года как параметр OpenAI "functions". Anthropic затем добавила блоки `tool_use` в Claude 2.1. Через несколько месяцев Gemini добавила `functionDeclarations`. Сейчас каждый provider предоставляет одну и ту же форму: на вход список инструментов, типизированный JSON Schema, на выход tool call как JSON payload. Model Context Protocol (ноябрь 2024) обобщил контракт так, чтобы один registry инструментов обслуживал любую модель. A2A (апрель 2026, v1.0) наложил тот же primitive на делегирование между агентами.

Четырехшаговый цикл — инвариант под всеми этими вариантами. Все остальное в Phase 13 является развитием этой идеи.

## Концепция

### Шаг первый: describe

Host объявляет каждый инструмент тремя полями.

- **Name.** Стабильный, машинно-читаемый идентификатор. `get_weather`, а не "weather thing".
- **Description.** Краткое описание на естественном языке в один абзац. "Используйте, когда пользователь спрашивает о текущих условиях в конкретном городе. Не используйте для исторических данных."
- **Input schema.** Объект JSON Schema (draft 2020-12), описывающий аргументы инструмента.

Модель получает этот список. Современные providers сериализуют такие объявления в system prompt через шаблон конкретного provider, поэтому вы как вызывающая сторона работаете только со структурированной формой.

### Шаг второй: decide

С учетом сообщения пользователя и доступных инструментов модель выбирает одно из трех поведений.

1. **Ответить напрямую** текстом. Без tool call.
2. **Вызвать один или несколько инструментов.** Выдать структурированные call-объекты. При `parallel_tool_calls: true` (по умолчанию в OpenAI и Gemini, opt-in в Anthropic) модель может выдать несколько вызовов за один turn.
3. **Отказаться.** Strict-mode structured outputs могут вернуть типизированный блок `refusal` вместо вызова.

Payload вызова инструмента имеет три устойчивых поля: call `id`, tool `name` и JSON-объект `arguments`. id нужен, чтобы host мог сопоставить последующий результат с конкретным вызовом; это важно, когда параллельные вызовы возвращаются не по порядку.

### Шаг третий: execute

Host получает вызов, валидирует аргументы по объявленной schema и запускает executor. Невалидные аргументы означают, что модель сгаллюцинировала поле или использовала неправильный тип — очень частый режим отказа у слабых моделей. Production hosts делают одно из трех: быстро завершают с ошибкой и показывают ее модели, чинят JSON constrained parser-ом или повторно вызывают модель, добавив validation error в prompt.

Сам executor — обычный код: Python, TypeScript, shell-команда или запрос к базе данных. Он производит результат, обычно строку, но это может быть любое JSON-значение или structured content block (text, image или ссылка на resource в MCP). Результат должен быть сериализуемым.

### Шаг четвертый: observe

Host добавляет результат инструмента в conversation (как сообщение с ролью `tool` и соответствующим `id`) и заново вызывает модель. Теперь у модели есть tool output в контексте, и она может выдать финальный ответ или запросить новые вызовы. Это продолжается, пока модель не перестанет выдавать calls или host не достигнет safety limit по числу итераций.

### Разделение доверия

Для безопасности важны два типа инструментов.

- **Pure.** Только чтение, детерминированные, без побочных эффектов. `get_weather`, `search_docs`, `get_current_time`. Их безопасно вызывать спекулятивно.
- **Consequential.** Меняют состояние, тратят деньги, затрагивают пользовательские данные. `send_email`, `delete_file`, `execute_trade`. Должны проходить через gate.

Правило Meta 2026 года "Rule of Two" для agent security говорит, что один turn может сочетать не более двух из трех: untrusted input, sensitive data, consequential action. Интерфейс инструментов — место, где вы обеспечиваете это правило: отклоняете вызовы, требуете подтверждение пользователя или повышаете scopes. Полная глава по безопасности — Phase 13 · 15, политики разрешений на уровне агента — Phase 14 · 09.

### Где живет цикл

| Контекст | Кто описывает | Кто решает | Кто выполняет |
|---------|---------------|-------------|--------------|
| Single-turn function calling (OpenAI/Anthropic/Gemini) | Разработчик приложения | LLM | Разработчик приложения |
| MCP | MCP server | LLM через MCP client | MCP server |
| A2A | Публикатор Agent Card | Вызывающий agent | Вызванный agent |
| Web browser (function-calling agent) | Browser extension / WebMCP | LLM | Browser runtime |

Везде одни и те же четыре шага. Названия колонок меняются; структура — нет.

### Почему не просто попросить модель выдать JSON?

"Попросить модель ответить JSON" было паттерном до function calling. Он ломается примерно в 5-15 процентах случаев на frontier models и значительно чаще на малых моделях. Режимы отказа: отсутствующие фигурные скобки, trailing commas, сгаллюцинированные поля и неправильные типы. После этого нужен проход исправления JSON, retry или constrained decoder.

Native function calling лучше по трем причинам. Во-первых, provider обучает модель end-to-end на точной форме вызова, поэтому доля валидного JSON поднимается до 98-99 процентов в strict mode. Во-вторых, call payload находится в отдельном protocol slot, а не внутри свободного текста, так что tool call не протекает в видимый пользователю ответ. В-третьих, providers обеспечивают schema compliance через constrained decoding (OpenAI strict mode, Anthropic `tool_use`, Gemini `responseSchema`). Output гарантированно валидируется.

Phase 13 · 02 разбирает три provider APIs рядом. Phase 13 · 04 глубоко разбирает structured outputs.

### Circuit breakers

Цикл завершается, когда модель перестает выдавать calls или host достигает максимального числа turns. Production hosts ставят это значение между 5 и 20 turns. Дальше вы почти наверняка попали в loop, из которого модель не может выйти. Claude Code по умолчанию использует 20; OpenAI Assistants — 10; Cursor's agent mode — 25.

Альтернатива — unbounded loops — каждые полгода появляется в post-mortems вида "agent spent $400 in API calls overnight". Не ship-ите без ограничения.

Phase 14 · 12 подробно покрывает восстановление после ошибок и self-healing; Phase 17 покрывает production rate limits.

## Используйте

`code/main.py` запускает четырехшаговый цикл без LLM. Фейковая функция "decider" симулирует модель через сопоставление шаблонов по сообщению пользователя; executor, schema validator и harness для observe-step настоящие. Запустите его, чтобы увидеть полную request/response choreography с печатаемым промежуточным состоянием, а в следующем уроке замените fake decider на любого реального provider.

На что смотреть:

- Tool registry хранит четыре поля на инструмент: name, description, schema и ссылку на executor.
- Validator — минимальное подмножество JSON Schema (types, required, enum, min/max), написанное только на stdlib. Phase 13 · 04 поставляет более полный вариант.
- Цикл ограничивает число итераций пятью. Production agents нуждаются именно в таком circuit breaker.

## Отправьте

Этот урок создает `outputs/skill-tool-interface-reviewer.md`. Получив черновик определения инструмента (name + description + schema + набросок executor), skill проверяет его пригодность к циклу: является ли name machine-stable, является ли description полным кратким описанием использования, корректно ли schema использует JSON Schema 2020-12 и явно ли указана классификация pure-vs-consequential.

## Упражнения

1. Добавьте в `code/main.py` четвертый инструмент `get_stock_price(ticker)`. Напишите его description как "Используйте, когда пользователь спрашивает текущую цену акции по тикеру. Не используйте для исторических цен или обзоров рынка." Запустите harness и подтвердите, что fake decider направляет queries с упоминанием tickers в новый инструмент.

2. Сломайте schema validator. Передайте call, у которого объект `arguments` не содержит required field, и подтвердите, что host отклоняет его до execution. Затем передайте call с лишним неизвестным полем. Решите: должен host отклонить его или проигнорировать? Обоснуйте выбор аргументом безопасности.

3. Классифицируйте каждый инструмент в harness как pure или consequential. Добавьте флаг `consequential: true` в registry entries, где он нужен, и измените цикл так, чтобы при выборе consequential tool печаталась строка "would confirm with user". Это форма confirmation gate, нужная каждому production host.

4. Нарисуйте четырехшаговый цикл на бумаге, заполнив таблицу выше с колонками provider для вашего любимого client (Claude Desktop, Cursor, ChatGPT или custom stack). Сверьте с MCP-specific вариантом в Phase 13 · 06.

5. Прочитайте руководство OpenAI по function calling от начала до конца. Найдите одно поле, которое находится в request, но не входит в четырехшаговый цикл в изложении здесь. Объясните, что оно добавляет и почему это удобно, но не существенно.

## Ключевые термины

| Термин | Как обычно говорят | Что это на самом деле означает |
|------|----------------|------------------------|
| Tool | "То, что модель может вызвать" | Тройка из name + входа, типизированного JSON Schema, + executor function |
| Function calling | "Нативное использование инструментов" | Provider-level API support для выдачи structured tool calls вместо prose |
| Tool call | "Запрос модели на действие" | JSON payload с `id`, `name`, `arguments`, выданный моделью |
| Tool result | "То, что вернул инструмент" | Output executor-а, завернутый в сообщение role `tool` с matching id |
| Parallel tool calls | "Много вызовов сразу" | Несколько call objects в одном model turn, независимые и упорядочиваемые по id |
| Strict mode | "Гарантированный JSON" | Constrained decoding, которое заставляет output модели валидироваться по declared schema |
| Pure tool | "Инструмент только для чтения" | Без побочных эффектов; безопасен для повторного запуска |
| Consequential tool | "Инструмент-действие" | Меняет external state; требует gate, audit или user confirmation |
| Four-step loop | "Цикл вызова инструмента" | describe → decide → execute → observe |
| Host | "Agent runtime" | Программа, которая держит tool registry, вызывает модель и запускает executor |
