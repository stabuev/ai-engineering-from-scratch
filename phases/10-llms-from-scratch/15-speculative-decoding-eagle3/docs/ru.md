# Спекулятивное декодирование и EAGLE-3

> Фаза 7 · Урок 16 доказал математику: правило отбраковки Leviathan точно сохраняет распределение верификатора. Этот урок рассматривает production-стек обучения для спекулятивного декодирования в 2026 году. EAGLE-3 превратил draft model из дешевого приближения в специально спроектированную крошечную сеть, обученную на собственных скрытых состояниях верификатора, а затем добавил training-time test loop, который согласует распределения обучения и инференса. Результат: сквозное ускорение от 3× до 6.5×, accepted per-token rates выше 0.9 в чате, без компромисса по распределению. Каждый production-стек инференса в 2026 году поставляет это по умолчанию.

## Проблема

Авторегрессионное декодирование на модели 70B работает, возможно, со скоростью 35 токенов в секунду на H100. GPU при этом далек от насыщения. Потолок задает пропускная способность памяти: каждый токен загружает 70B весов из HBM, выполняет один шаг арифметики и производит один float. Вычислительные блоки большую часть времени простаивают.

Speculative decoding превращает это в задачу пропускной способности, которую действительно можно решить. Дешевый draft предлагает `N` токенов за `N` небольших forward pass. Верификатор один раз запускается на префиксе плюс всех `N` draft-токенах. Если распределение верификатора в позиции `i` согласуется с draft (в статистическом смысле, который мы уточним), мы принимаем; если нет, отбраковываем и сэмплируем исправление из residual distribution. Один forward большой модели производит до `N+1` принятых токенов вместо одного.

Ключевая теорема принадлежит Leviathan, Kalman, Matias (ICML 2023): выходное распределение идентично тому, которое получилось бы при прямом сэмплировании из верификатора. Не приблизительно. Идентично. Именно поэтому speculative decoding допустимо в production: это чистая оптимизация задержки без компромисса по качеству.

Фаза 7 · Урок 16 дала вам математику. Этот урок дает вам стек обучения. Хороший draft дает в 2× больше ускорения, чем просто дешевый draft. EAGLE, EAGLE-2 и EAGLE-3 (Li et al., 2024–2025) превратили идею "draft = уменьшенная версия той же модели" в точную инженерную дисциплину. В 2026 году production-серверы инференса по умолчанию используют EAGLE-3.

## Концепция

### Инвариант: rejection sampling Leviathan

Пусть `p(t)` — распределение draft для следующего токена при некотором префиксе, а `q(t)` — распределение верификатора. Сэмплируем draft-токен `d ~ p`. Принимаем с вероятностью `min(1, q(d) / p(d))`. При отбраковке сэмплируем из residual distribution `(q - p)_+ / ||(q - p)_+||_1`. Полученные сэмплы распределены согласно `q`. Это верно независимо от того, насколько плох `p`: чем оно хуже, тем чаще будут отбраковки, но выход остается точным.

Сложите `N` таких вызовов подряд, используя один forward pass верификатора на `prefix + d_1 + ... + d_N`. Верификатор одновременно возвращает `q_1, q_2, ..., q_{N+1}`. Идем слева направо. При первой отбраковке в позиции `j` сэмплируем из `residual(q_j, p_j)` и останавливаемся. При полном принятии сэмплируем один bonus token из `q_{N+1}`.

### От чего зависит ускорение

Пусть `α` — ожидаемый acceptance rate на каждый draft-токен. Пусть `c = cost(draft) / cost(verifier)` — отношение стоимостей. Ожидаемое число принятых токенов на один forward верификатора:

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

Ожидаемое полное wall time на принятый токен равно `(N * c + 1) / E[accepted]`. Минимизируйте это по `N`, и получите оптимальную точку. Для `α = 0.8, c = 0.05`: оптимальное `N` примерно 5–7, ускорение 3.2×. Для `α = 0.95, c = 0.02`: оптимальное `N` примерно 8–10, ускорение приближается к 5×.

Самый мощный рычаг — `α`. Переход от `α = 0.6` (vanilla draft) к `α = 0.9` (EAGLE-3) при фиксированном `N = 5` переводит вас с 2.2 ожидаемых принятых токенов на forward верификатора к 4.1. Почти 2× дополнительной пропускной способности на том же верификаторе.

### Двухлетняя эволюция

**Vanilla speculative (Leviathan, 2023).** Draft model — независимо обученная меньшая LLM из того же семейства. Легко подключить, `α ≈ 0.6`, ускорение в лучшем случае около 2×.

**EAGLE-1 (Li et al., 2024).** Draft — крошечный transformer, обычно один или два слоя, который принимает скрытое состояние последнего слоя верификатора и напрямую предсказывает следующий токен. Поскольку draft видит признаковое представление верификатора, его распределение намного ближе к распределению верификатора. `α` поднимается до 0.7–0.8.

**EAGLE-2 (Li et al., 2024).** Добавляет динамическое draft tree: вместо предложения одной последовательности из `N` токенов предлагается небольшое дерево кандидатов, каждый оценивается верификатором за один forward pass (tree attention), а затем выбирается путь с наибольшей вероятностью. Длина draft становится адаптивной на каждом шаге. `α` на токен принятого пути поднимается выше 0.85.

**EAGLE-3 (Li et al., 2025, NeurIPS).** Еще два изменения. Во-первых, полностью убирается feature-prediction loss: EAGLE-1/2 обучали draft совпадать со скрытыми состояниями верификатора, что ограничивает пользу от роста данных. EAGLE-3 обучается напрямую на предсказание токенов. Во-вторых, training-time test (TTT): во время обучения draft его собственные предыдущие предсказания подаются обратно на вход в течение нескольких шагов, так же как это происходит при инференсе. Это согласует распределения train и test и останавливает накопление ошибок. Измеренное ускорение: до 6.5× в чате, улучшение пропускной способности на 38% при batch 64 в SGLang на H100.

### Откат KV cache

Верификация расширяет KV cache верификатора на `N` записей за один проход. Если отбраковка происходит в позиции `j`, содержимое cache после позиции `j-1` теперь неверно. Две распространенные реализации: писать в scratch buffer и commit при принятии (vLLM, TensorRT-LLM) или держать физический KV cache плюс логическую длину и truncate при отбраковке. В любом случае стоимость rollback — это байты на слой и голову, что пренебрежимо мало рядом со стоимостью forward-pass.

Для tree search в EAGLE-2 верификатор запускает attention с non-causal mask, которая соблюдает топологию дерева. Инженерно это аккуратная, но хлопотная часть; вычислительно это стандартный вызов flash-attention с custom mask.

### Архитектуры draft в 2026 году

| Strategy | Draft type | `α` | Speedup | Training cost |
|----------|-----------|-----|---------|---------------|
| Vanilla | Отдельная малая LLM | 0.55-0.70 | 1.8-2.3× | Нет (повторное использование существующей малой модели) |
| Medusa | Дополнительные LM heads на верификаторе | 0.65-0.75 | 2-3× | ~1B SFT tokens |
| EAGLE-1 | 1-layer transformer на hidden states | 0.70-0.80 | 2.5-3× | ~60B tokens |
| EAGLE-2 | EAGLE-1 + dynamic draft tree | 0.80-0.88 | 3-4× | ~60B tokens |
| EAGLE-3 | Multi-layer feature fusion + TTT | 0.88-0.92 | 3.5-6.5× | ~60-200B tokens |
| Lookahead | Без draft (Jacobi iteration) | N/A | 1.3-1.6× | Нет |

В production 2026 года: vLLM и SGLang по умолчанию используют EAGLE-3, когда он доступен, иначе EAGLE-2. TensorRT-LLM имеет самый быстрый путь Medusa для публичных моделей Meta и NVIDIA. llama.cpp поставляет vanilla draft для CPU-развертываний.

## Соберите это

См. `code/main.py`. Это полный speculative loop Leviathan со всеми частями: draft-of-N, параллельный проход верификатора, отбраковка по позициям, residual sampling, bonus token, KV rollback и эмпирическая проверка, что выходное распределение совпадает с прямым сэмплированием из `q`.

### Шаг 1: правило отбраковки

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### Шаг 2: residual distribution

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### Шаг 3: полный speculative step

Функция `spec_step` создает draft из `N` токенов из `p`, затем проверяет их все одной параллельной оценкой `q`. Для каждого draft-токена она применяет правило отбраковки, а при первой отбраковке сэмплирует исправление из residual. Если все принято, она выдает bonus token из `q_{N+1}`.

### Шаг 4: учет KV rollback

Симулятор отслеживает логический `kv_length` для каждого worker. При принятии `k` draft-токенов выполняется `kv_length += k`. При отбраковке в позиции `j` cache уже записан дальше `j`, но логическая длина устанавливается в `prefix_length + j + 1` — на один после токена-исправления. Последующие чтения усекаются до логической длины.

### Шаг 5: проверка Leviathan

Запустите 50,000 speculative steps. Подсчитайте эмпирическое распределение принятых токенов. Сравните с 50,000 прямыми сэмплами из `q`. Статистика chi-square должна быть существенно ниже критического значения. Теорема проходит практическую проверку.

SGLang с EAGLE-3 при batch 64 на H100: примерно в 1.38× больше пропускной способности, чем batch-64 vanilla decoding, согласно статье EAGLE-3.

Когда стоит использовать speculative decoding:

- Любая interactive chat workload, где p50 latency важнее пиковой пропускной способности.
- Code generation и structured output (JSON, SQL). `α` выше 0.9, потому что целевое распределение хорошо предсказуемо.
- Long-form generation (тысячи токенов). Амортизированное ускорение продолжает окупаться.

Когда не стоит:

- Очень маленькие модели (< 3B). Draft не настолько дешевле верификатора.
- Крошечные batch-1 CPU-развертывания. Memory overhead draft model может не окупиться.
- Very-high-temperature creative sampling, где `α` обрушивается.

## Ключевые термины

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Leviathan rule | "min(1, q over p)" | Bernoulli accept/reject с вероятностью `min(1, q(d)/p(d))`; точно сохраняет распределение верификатора, когда при отбраковке вы сэмплируете из residual |
| Residual distribution | "(q minus p) plus, normalized" | `(q - p)_+`, обрезанное снизу нулем и перенормированное — корректное распределение для сэмплирования при отбраковке |
| Acceptance rate α | "how often the draft is right" | Ожидаемая вероятность Bernoulli-success на токен по правилу отбраковки; управляет всей математикой ускорения |
| EAGLE-1 | "hidden-state draft" | Крошечный transformer draft, обусловленный скрытым состоянием последнего слоя верификатора (Li et al., 2024) |
| EAGLE-2 | "dynamic draft tree" | EAGLE-1 плюс дерево candidate continuations, оцениваемое с tree attention за один проход верификатора |
| EAGLE-3 | "training-time test" | Убирает feature-prediction loss, обучается на прямом предсказании токенов с подачей собственных выходов draft во время обучения |
| Training-time test (TTT) | "exposure bias fix" | Запускать draft авторегрессионно во время обучения, чтобы распределения входов train и test совпадали — прямой аналог scheduled sampling |
| KV rollback | "undo rejected drafts" | Учет, который сбрасывает KV cache верификатора к длине принятого префикса после отбраковки |
| Bonus token | "the free one" | Когда все `N` draft-токенов приняты, сэмплировать один дополнительный из `q_{N+1}` без дополнительной стоимости верификатора |
| Tree attention | "verify many candidates at once" | Attention с non-causal mask, соблюдающей топологию draft tree; вычисляет `q_i` для каждого узла дерева за один forward pass |
