# MIO и потоковые мультимодальные модели any-to-any

> GPT-4o поставляет продукт, который большинство открытых моделей не может воспроизвести: агента, который слышит голос, видит видео и отвечает речью в реальном времени. Ответом открытой экосистемы к концу 2024 года стала MIO (Wang et al., сентябрь 2024). MIO токенизирует текст, изображение, речь и музыку, обучает один каузальный трансформер на чередующихся последовательностях и генерирует любую модальность в любую модальность. AnyGPT (Zhan et al., февраль 2024) была проверкой концепции; MIO — масштабирование этой идеи; Unified-IO 2 (Allen AI, декабрь 2023) — родственная модель с привязкой зрения + действий. В этом уроке разбирается паттерн any-to-any — четыре токенизатора, один трансформер, декодирование, удобное для стриминга.

**Тип:** Изучение
**Языки:** Python (stdlib, four-modality token allocator + streaming decode loop)
**Предварительные требования:** Phase 12 · 11 (Chameleon), Phase 6 (Speech and Audio)
**Время:** ~120 минут

## Цели обучения

- Спроектировать общий словарь, который размещает токены текста, изображения, речи и музыки без коллизий.
- Сравнить SEED-Tokenizer (изображения) и SpeechTokenizer residual-VQ (речь) по компромиссам сжатия и восстановления.
- Объяснить четырехэтапный учебный план, который наращивает генерацию any-to-any.
- Назвать три открытых рецепта any-to-any и их основные компромиссы: MIO, AnyGPT, Unified-IO 2.

## Проблема

Единую мультимодальную модель легко заявить и трудно построить в масштабе. Большинство систем "any-to-any" до 2024 года были конвейерными: модель зрения → текстовое представление → речевая модель → аудио. Каждый переход теряет информацию, добавляет задержку и усложняет обучение. Демовидео GPT-4o показало альтернативу в виде одной модели с ответом меньше чем за секунду; открытые системы отставали на месяцы.

Инженерные проблемы:

- Токенизаторы должны существовать для каждой модальности, сжимать достаточно без потерь для восстановления и выдавать токены с частотой, которую трансформер может потреблять.
- Один словарь должен выделить место для текста (32k+), изображений (16k+), речи (4k+), музыки (8k+). Минимум более сорока тысяч элементов.
- Обучающие данные должны покрывать каждую пару вход-выход (text→image, image→speech, speech→image и т. д.), либо модель должна уметь компоновать.
- Инференс должен стримить выходные токены достаточно быстро для разговорной задержки (<500ms time-to-first-audio-byte).

## Концепция

### Four tokenizers for four modalities

Стек токенизаторов MIO:

- Text: стандартный BPE, словарь ~32000.
- Image: SEED-Tokenizer (2023) — квантованный VAE с дискретным codebook, 4096 элементов, 32x32 токена на изображение.
- Speech: SpeechTokenizer residual-VQ (2023) — кодирует waveform 16kHz в 8 иерархических codebook; первый уровень — грубое содержание, поздние уровни добавляют просодию и идентичность говорящего.
- Music: похожий residual-VQ (семейство Meta MusicGen / Encodec), 4-8 codebooks.

Каждая модальность производит целочисленные токены. Токены получают непересекающиеся диапазоны ID в общем словаре:

```
text:   0..31999
image:  32000..36095  (4096 image tokens)
speech: 36096..40191  (4096 speech base tokens, plus residual layers)
music:  40192..48383  (8192 music tokens)
sep:    48384..48390  (<image>, <speech>, <music>, </...>, etc.)
```

Итого: словарь ~48k. Входной embedding и выходная проекция охватывают его целиком.

### Streaming decode

Генерация речи использует residual-VQ. Трансформер предсказывает базовые речевые токены (layer 0); параллельно декодируемый остаточный квантователь предсказывает последующие уровни. Каждый токен layer 0 соответствует примерно 50ms аудио при 16kHz.

Потоковый паттерн:

1. Пользователь говорит в микрофон; токенизатор аудио реального времени выдает речевые токены каждые 50ms.
2. MIO потребляет токены по мере их поступления (prompt prefill + incremental forward).
3. Выходные токены стримятся по мере генерации; параллельный речевой декодер преобразует их в аудиосэмплы с задержкой ~50-150ms.
4. Time-to-first-audio-byte: ~300-500ms в статье MIO, приближаясь к ~250ms у GPT-4o.

Mini-Omni (arXiv:2408.16725), GLM-4-Voice (arXiv:2412.02612) и Moshi (arXiv:2410.00037) — дополняющие проекты потоковых speech-LLM. В частности, Moshi достигает 160ms round-trip на одном GPU.

### Four-stage curriculum

Учебный план MIO:

1. Stage 1 — alignment. Крупномасштабные корпуса пар модальностей: text-image, text-speech, text-music. Каждая пара использует свой сегмент словаря токенов. Обучает общий словарь.
2. Stage 2 — interleaved. Мультимодальные чередующиеся документы (блоги с изображениями + видео, подкасты с транскриптами и т. д.). Обучает межмодальный контекст.
3. Stage 3 — speech-enhanced. Дополнительные аудиоданные для повышения качества речи без потери текстовых возможностей.
4. Stage 4 — SFT. Инструктивная донастройка по модальностям: VQA, captioning, narration, speech-to-speech dialogue.

Пропуск этапа ухудшает конкретные возможности: пропустите stage 2 — модель потеряет межмодальный контекст; пропустите stage 3 — речь будет плохой.

### Chain-of-visual-thought

MIO вводит chain-of-visual-thought: модель выдает промежуточные токены изображения как шаг рассуждения. Для вопроса "is the cat climbing a tree?" модель:

1. Выдает токены `<image>`, визуализирующие сцену (из входного изображения или эскиза).
2. Выдает текст с анализом эскиза.
3. Выдает финальный ответ.

Визуализированное промежуточное изображение служит черновиком. Метрики улучшаются на задачах пространственного рассуждения. Идея отражает chain-of-thought для текстового рассуждения.

### Competitors in any-to-any

- AnyGPT (arXiv:2402.12226): 4 модальности (текст, изображение, речь, музыка), похожий дизайн.
- Unified-IO 2 (arXiv:2312.17172): добавляет выходы действий зрения, глубину, нормали. Больше разнообразия задач, меньший масштаб.
- NExT-GPT (arXiv:2309.05519): LLM + модально-специфичные diffusion-декодеры. Не подход с одной моделью.
- CoDi (arXiv:2305.11846): компонуемая диффузия; any-to-any через общий latent.

MIO ближе всего к чисто токенному any-to-any. AnyGPT — ее концептуальный предок.

### Latency budget

Для разговорного продукта важна задержка каждого компонента:

- Mic to audio tokens: ~50ms.
- Prefill (audio tokens + history): ~100ms на модели 8B.
- First output token: ~50ms.
- Parallel residual-VQ + speech decoder: ~100-150ms.

Общее time-to-first-audio-byte: минимум ~300ms. GPT-4o заявляет ~250ms. Moshi заявляет 160ms. MIO/AnyGPT находятся в диапазоне 400-600ms по публичным бенчмаркам.

### Why any-to-any stays hard

Даже в 2026 году открытые any-to-any модели отстают от закрытых по двум осям:

- Качество речи. Токенизатор residual-VQ имеет потери; разговорная речь звучит роботизированно по сравнению с голосами класса ElevenLabs.
- Межмодальное рассуждение. Просьба к модели "sing about what you see" все еще проваливается чаще, чем чистые vision-задачи.

Это открытые исследовательские проблемы. Qwen3-Omni (Lesson 12.20) — самая продвинутая открытая попытка в 2025 году.

## Использование

`code/main.py`:

- Вычисляет ожидаемое time-to-first-audio-byte с учетом задержек encoder, prefill и decoder.

## Ключевые термины

| Термин | Как говорят | Что это на самом деле означает |
|------|-----------------|------------------------|
| Any-to-any | "Multimodal in/out" | Одна модель, которая принимает и выдает текст, изображение, речь и музыку в любом направлении |
| Residual-VQ | "Speech tokenizer stack" | Многокодбуковая токенизация, где каждый слой добавляет информацию; базовый слой — содержание, поздние слои — просодия |
| SEED-Tokenizer | "Image codes" | Дискретный токенизатор изображений с codebook на 4096 элементов, используемый MIO |
| Chain-of-visual-thought | "Visual scratchpad" | Модель генерирует промежуточное изображение как шаг рассуждения перед финальным ответом |
| Time-to-first-audio-byte | "TTFAB" | Задержка от голоса пользователя до первого аудиовыхода; <500ms для ощущения разговора |
| Four-stage curriculum | "Training recipe" | Alignment -> interleaved -> speech-enhanced -> SFT, в этом порядке |
