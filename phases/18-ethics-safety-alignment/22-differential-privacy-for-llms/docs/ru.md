# Дифференциальная приватность для LLM

> DP-SGD остается стандартом — обновления градиентов с добавлением шума дают формальные гарантии (epsilon, delta). Накладные расходы по вычислениям, памяти и полезности существенны; parameter-efficient DP fine-tuning (LoRA + DP-SGD) — распространенная конфигурация 2025 года (ACM 2025). Два массива свидетельств находятся в напряжении: membership inference на основе canary (Duan et al., 2024) сообщает об ограниченном успехе против языковых моделей; extraction обучающих данных (Carlini et al., 2021; Nasr et al., 2025) извлекает значительное дословное запоминание. Разрешение (arXiv:2503.06808, март 2025): разрыв в том, что именно измеряется — вставленные canaries против "наиболее извлекаемых" данных. Новые дизайны canary позволяют loss-based MIA без shadow models и дают первый нетривиальный DP-аудит LLM, обученной на реальных данных с реалистичными DP-гарантиями. Альтернативы: PMixED (arXiv:2403.15638) — приватное предсказание во время инференса через mixture of experts по распределениям следующего токена; генерация DP-синтетических данных (Google Research 2024). Возникающая атака: Differential Privacy Reversal via LLM Feedback — утечка через confidence-score.

## Проблема

LLM запоминают. Carlini et al. 2021 показали, что production-языковые модели воспроизводят дословный обучающий текст по запросу. DP — формальная защита: обучать так, чтобы выход был доказуемо нечувствителен к любому одному обучающему примеру. Свидетельства 2024-2025 показывают, что DP-SGD необходим, но развернутые значения ε могут не соответствовать модели угроз.

## Концепция

### (ε, δ)-дифференциальная приватность

Рандомизированный алгоритм M является (ε, δ)-DP, если для любых двух наборов данных, различающихся одним примером, и любого события S:
P(M(D) in S) <= e^ε * P(M(D') in S) + δ.

Интерпретация: выходное распределение достаточно близко (параметризовано ε), чтобы вклад любого отдельного человека нельзя было надежно вывести, кроме как с вероятностью δ.

### DP-SGD

Abadi et al. 2016. Стандартный рецепт:
1. Выбрать mini-batch.
2. Вычислить градиенты по каждому примеру.
3. Обрезать каждый per-example gradient до порога C.
4. Суммировать обрезанные градиенты и добавить гауссов шум со std σ * C.
5. Использовать зашумленную сумму для обновления параметров.

Стоимость приватности отслеживается accountant (Moments Accountant, Rényi DP accountant). Сообщаемые значения ε в литературе по LLM сильно различаются по модели угроз, чувствительности данных и целевой полезности; универсально "безопасного" значения ε по умолчанию нет. Опубликованные примеры охватывают примерно ε ≈ 1–10 в некоторых настройках обучения LLM, но это иллюстрации, а не рекомендуемые значения по умолчанию. Более низкое ε обычно требует большего шума и может увеличивать потерю полезности.

### LoRA + DP-SGD

Полный DP-SGD frontier-модели непомерно дорог. LoRA (Hu et al. 2022) ограничивает обновления градиентов небольшим адаптером, уменьшая хранение per-example gradients. LoRA + DP-SGD — распространенная конфигурация 2025 года. DP-гарантии применяются к адаптеру; базовая модель остается фиксированной.

### Напряжение 2024-2025

Две линии свидетельств:

- **Canary MIA (Duan et al. 2024).** Вставляют уникальные canaries в обучающие данные, измеряют, может ли membership-inference attacker их идентифицировать. Сообщает об ограниченном успехе на языковых моделях. Предполагает, что MIA трудна.
- **Training-data extraction (Carlini 2021, Nasr et al. 2025).** Подсказывают модели prefix; измеряют, восстанавливает ли она дословный текст из обучения. Сообщает о существенном запоминании. Предполагает, что MIA проста в релевантном смысле.

Разрешение марта 2025 (arXiv:2503.06808): они измеряют разные вещи. MIA спрашивает "есть ли example e в D?" на вставленных canaries. Extraction спрашивает "что я могу восстановить из D?" Для приватности важен "most extractable" пример; canaries недооценивают это, потому что они не оптимизированы быть извлекаемыми.

Новые дизайны canary. Loss-based MIA без shadow models. Первый нетривиальный DP-аудит LLM на реальных данных с реалистичными DP-гарантиями.

### Альтернативы DP-обучению

- **PMixED (arXiv:2403.15638).** Приватное предсказание во время инференса. Mixture of experts по распределениям следующего токена; каждый expert видит шард обучающих данных; агрегация добавляет шум для DP. Полностью избегает DP-обучения.
- **Генерация DP-синтетических данных (Google Research 2024).** LoRA-fine-tune с DP-SGD, сэмплировать синтетические данные, обучить downstream-классификатор на синтетических данных.

Оба подхода обходят стоимость полезности полного DP-обучения ценой другой модели угроз.

### Differential Privacy Reversal via LLM Feedback

Возникающая атака 2025 года. Использовать confidence scores DP-обученной модели как оракул для повторной идентификации людей. Даже когда выходы не утекают, confidence distributions могут утекать.

Защита: не раскрывать confidence, либо усекать/квантизовать их перед раскрытием. Это дополнительное требование сверх (ε, δ)-DP-обучения.

## Применение

`code/main.py` симулирует DP-SGD на игрушечном наборе данных бинарной классификации. Можно перебирать noise multiplier σ и clipping norm C и отслеживать бюджет (ε, δ) и стоимость точности. "canary attack" вставляет уникальный обучающий пример и измеряет, может ли log-loss test обнаружить его до и после DP.

## Ключевые термины

| Термин | Как обычно говорят | Что это на самом деле означает |
|------|-----------------|------------------------|
| DP | "(ε, δ)-differential privacy" | Формальная приватность: выходное распределение близко при изменении соседнего набора данных |
| DP-SGD | "noise-injected SGD" | Обрезание градиентов + добавление гауссова шума; стандартное DP-обучение |
| LoRA + DP-SGD | "efficient private fine-tune" | DP-SGD на low-rank adapters; стандартная конфигурация 2025 года |
| MIA | "membership inference" | Атака, определяющая, был ли пример в обучающих данных |
| Canary | "inserted watermark example" | Уникальный обучающий пример, используемый для измерения DP-утечки |
| PMixED | "private inference mixture" | DP во время инференса через mixture-of-experts по распределениям следующего токена |
| DP Reversal | "confidence leakage attack" | Атака, использующая confidence модели как оракул для повторной идентификации |
