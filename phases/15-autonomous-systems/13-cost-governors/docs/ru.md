# Бюджеты действий, лимиты итераций и регуляторы затрат

> Месячная стоимость LLM у агента среднего e-commerce выросла с $1,200 до $4,800 после того, как команда включила навык "order-tracking". Это не ошибка ценообразования. Это агент, который нашел новый цикл и продолжил тратить внутри него. Microsoft Agent Governance Toolkit (2 апреля 2026 года) кодифицирует защиту от этого класса проблем: `max_tokens` на запрос, токенные и долларовые бюджеты на задачу, дневные/месячные лимиты, лимиты итераций, многоуровневую маршрутизацию моделей, кэширование промптов, оконную работу с контекстом, HITL-контрольные точки для дорогих действий, kill switch при нарушении бюджета. Anthropic Claude Code Agent SDK поставляет те же примитивы под другими именами. Ограничения финансовой скорости — например, отключить доступ при >$50 за 10 минут — ловят циклы быстрее, чем месячные лимиты.

**Тип:** Изучение
**Языки:** Python (stdlib, симулятор многоуровневого регулятора затрат)
**Предварительные требования:** Фаза 15 · 10 (Режимы разрешений), Фаза 15 · 12 (Надежное выполнение)
**Время:** ~60 минут

## Цели обучения

- Объяснять, как включение одного навыка может взорвать месячную стоимость агента.
- Проектировать cost governor с бюджетами, лимитами по навыкам и атрибуцией.
- Связывать контроль стоимости с режимом отказа длинного горизонта.

## Проблема

Автономные агенты тратят реальные деньги на каждом шаге. Плохой ответ чат-бота — это плохая реплика; плохой цикл агента — это счет к оплате. Задокументированный в индустрии термин для этого режима отказа — "Denial of Wallet": агент продолжает рассуждать, продолжает вызывать инструменты, продолжает начислять расходы, и ничто его не останавливает, потому что ничего для этого не было спроектировано.

Исправление — это не одно число. Это стек лимитов на разных временных масштабах и уровнях детализации: на запрос, на задачу, на час, на день, на месяц. Хорошо спроектированный стек ловит runaway loop за минуты, медленную утечку — за часы, а плохой релиз — за день. Тот же стек в целом удерживает бюджет, когда агент долгосрочный и автономный.

Это инженерный урок: математика тривиальна, команды проваливаются в дисциплине. Все лимиты ниже названы либо в Microsoft Agent Governance Toolkit, либо в документации Anthropic Claude Code Agent SDK.

## Концепция

### Стек регулятора затрат

1. **`max_tokens` на запрос.** Просто. Не дает одному вызову породить неограниченное завершение.
2. **Токенный бюджет на задачу.** За весь запуск не превышать N токенов. Жесткая остановка на лимите.
3. **Долларовый бюджет на задачу.** То же, что токены, но в валюте. `max_budget_usd` в Claude Code.
4. **Лимит вызовов на инструмент.** Не больше N вызовов `WebFetch`, N вызовов `shell_exec` и т. д.
5. **Лимит итераций (`max_turns`).** Общее число итераций агентного цикла; предотвращает бесконечные циклы рассуждения.
6. **Лимит на минуту / час / день / месяц.** Скользящие окна. Ловит утечки на разных временных масштабах.
7. **Ограничение финансовой скорости.** Например: "если расходы превышают $50 за 10 минут, отключить доступ." Ловит сжигание бюджета в цикле до того, как сработают месячные лимиты.
8. **Многоуровневая маршрутизация моделей.** По умолчанию использовать меньшую модель; повышать до более крупной только когда классификатор считает, что задача этого требует.
9. **Кэширование промптов.** Системный промпт и стабильный контекст хранятся в кэше провайдера; токенная стоимость повторной отправки близка к нулю.
10. **Оконная работа с контекстом.** Компактизация / суммаризация, чтобы держать активный контекст ниже порога; прямое снижение токенной стоимости.
11. **HITL-контрольные точки для дорогих действий.** Перед действием, которое известно как дорогое (долгий вызов инструмента, большая загрузка, дорогое повышение модели), требовать подтверждение человека.
12. **Kill switch при нарушении бюджета.** Сессия прерывается, когда срабатывает любой лимит. Сработавший лимит записывается; для восстановления нужен отдельный путь повторного включения.

### Почему стек, а не один лимит

Один месячный лимит ловит runaway agent только после того, как кошелек уже опустел. Один лимит на запрос ничего не ловит на уровне сессии. Разным режимам отказа нужны разные временные масштабы:

- **Runaway loop** (агент застрял в 5-секундном retry): ловится ограничением скорости.
- **Медленная утечка** (агент делает примерно в 2 раза больше ожидаемой работы на задачу): ловится дневным лимитом.
- **Плохой релиз** (новая версия использует в 5 раз больше токенов): ловится недельным / месячным лимитом.
- **Легитимный всплеск** (реальный спрос, не баг): ловится часовым / дневным лимитом с понятным логом.

### Бюджетная поверхность Claude Code

Claude Code Agent SDK предоставляет (публичная документация):

- `max_turns` — лимит итераций.
- `max_budget_usd` — долларовый лимит; сессия прерывается при нарушении.
- `allowed_tools` / `disallowed_tools` — allowlist и denylist инструментов.
- Hook points перед использованием инструментов для кастомного учета затрат.

Сочетайте это с лестницей permission-mode (Урок 10). Сессия `autoMode` без `max_budget_usd` — это неуправляемая автономность. Anthropic прямо описывает Auto Mode как режим, требующий бюджетных контролей; классификатор ортогонален затратам.

### EU AI Act, OWASP Agentic Top 10

Microsoft Agent Governance Toolkit покрывает OWASP Agentic Top 10 и требования EU AI Act Article 14 (человеческий надзор). Для продакшена в ЕС логирование и принудительное применение лимитов не опциональны.

### Наблюдавшийся случай $1,200 → $4,800

Реальный случай из документации Microsoft: e-commerce агент, чья месячная стоимость утроилась после добавления нового инструмента. Инструмент позволял агенту опрашивать статус заказа в каждой сессии. Нет детекции циклов. Нет лимита на инструмент. Нет алерта на рост неделя к неделе. Исправлением стал лимит на инструмент плюс алерт на дневной рост. Это шаблон: каждая новая поверхность инструмента — новый потенциальный цикл; каждому новому инструменту нужен собственный лимит и собственный алерт.

## Используйте это

`code/main.py` симулирует запуск агента с многоуровневым стеком регулятора затрат и без него. Симулированный агент после нескольких шагов уходит в polling loop; многоуровневый стек ловит это в окне скорости, тогда как один месячный лимит сработал бы только через несколько дней.

## Отгрузите это

`outputs/skill-agent-budget-audit.md` аудирует стек регулятора затрат для предлагаемого развертывания агента и отмечает отсутствующие уровни.

## Упражнения

1. Запустите `code/main.py`. Убедитесь, что ограничение скорости срабатывает раньше лимита итераций на траектории polling-loop. Теперь отключите ограничение скорости и измерьте, сколько агент "потратит", прежде чем его поймает лимит итераций.

2. Спроектируйте набор лимитов на инструменты для browser agent (Урок 11). Какому инструменту нужен самый жесткий лимит? Какой инструмент может выполняться без ограничений без риска?

3. Прочитайте документацию Microsoft Agent Governance Toolkit. Перечислите каждый тип лимита, который называет toolkit. Сопоставьте каждый с одним из режимов отказа (runaway loop, медленная утечка, плохой релиз, всплеск).

4. Оцените стоимость ночного unattended run для реалистичной задачи (например, "triage 50 issues in a repo"). Установите `max_budget_usd` на уровне 2x от вашей точечной оценки. Обоснуйте множитель 2x.

5. `max_budget_usd` в Claude Code срабатывает на агрегированной стоимости сессии. Спроектируйте дополнительное ограничение скорости, которое вы бы применяли снаружи. Что запускает отсечение и как выглядит повторное включение?

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|---|---|---|
| Denial of Wallet | "Разбегающийся счет" | Цикл агента генерирует расходы без лимита, который мог бы его остановить |
| max_tokens | "Лимит на запрос" | Верхняя граница размера одного completion |
| max_turns | "Лимит итераций" | Верхняя граница итераций агентного цикла в сессии |
| max_budget_usd | "Долларовый kill switch" | Лимит стоимости сессии; прерывает при нарушении |
| Velocity limit | "Ограничение скорости" | Лимит расходов за короткое окно (например, $50 / 10 min) |
| Tiered routing | "Сначала малая модель" | Дешевая модель по умолчанию; повышение только когда классификатор считает нужным |
| Prompt caching | "Кэшированный системный промпт" | Кэш на стороне провайдера снижает стоимость повторной отправки токенов почти до нуля |
| HITL checkpoint | "Шлюз подтверждения человеком" | Перед дорогим действием требуется подтверждение человека |
