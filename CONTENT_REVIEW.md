Содержание **сильное и действительно дописанное** — следов заглушек
(`TODO`/`placeholder`/lorem) в доках нет, переводы ru/en построчно параллельны

**Почему P12 — приоритет №1 по диаграммам:** это фаза про *архитектуры* —
BLIP-2 Q-Former, Flamingo gated cross-attention, LLaVA, Chameleon early-fusion,

курсе умеют делать диаграммы — нужно перенести практику на P12.

**Предложение:** добавить ≥1 mermaid/ASCII-диаграмму в каждый
архитектурный/пайплайновый урок, начиная с P12, затем P6/P9/P13. Это не
переписывание — это врезки в уже готовый текст.

### B. «Learning Objectives» — непоследовательны, хотя шаблон их теперь требует

Есть у **279/434 (64%)**. Распределение бинарное — фаза либо вся с целями,
либо вся без:

- **Полностью с целями:** P0–P4, P10–P14, P17, P18 (свежие/переработанные фазы).
- **Полностью без:** P5 (0/29), P6 (0/17), P8 (0/15), P9 (0/12), P15 (0/22),
  P19 (0/17); P7 — 1/16, P16 — 2/25.

После прогона 3 `LESSON_TEMPLATE.md` прописывает секцию «Learning Objectives»
как стандарт — значит 155 уроков теперь формально не соответствуют
собственному шаблону. Цели дёшево добавить (3–5 буллетов из уже написанного
текста) и они заметно улучшают навигацию и работу скилла `/check-understanding`.

**Предложение:** добить «Learning Objectives» в 8 фазах без них. Это
механическая, но высокоокупаемая правка — можно даже полу-автоматизировать
(сгенерировать черновик из секций урока, затем вычитать).

Не arxiv-придирка (применённые фазы P13/14/17 честно ссылаются на спеки MCP,

**Предложение:** проставить DOI/arxiv/каноничные URL в Further Reading фаз 1 и 3.

## Глазами новичка: хватило бы мне всего, если бы я учился по этому курсу?

Отдельная проверка под другим углом. Структурный аудит выше отвечает на вопрос
«есть ли секции». Этот раздел — на вопрос «можно ли реально пройти курс, не
застряв». Проверяла эмпирически: запускала первый урок, искала решения
упражнений, проверяла воспроизводимость зависимостей, флаги железа/денег,
навигацию, плотность жаргона.

### Короткий ответ

**Читать и понимать — да, хватит.** Педагогика честно хорошая, и это видно по
деталям, которые новичок чувствует: вход в курс мягкий и правильно
настроенный (P1/01: «Вы не обязаны быть математиком — нужно увидеть, что
операции значат геометрически, и закодить их самому»), структура «зачем →
как → с нуля → потом фреймворк» — ровно то, что строит понимание, а не
копипаст. **426 из 426** кода-файлов печатают результат и запускаются
автономно (первый запуск из README прошёл с ходу, rc=0). Это не курс-обманка.

**Но самостоятельно дойти до конца, не застряв, — местами трудно.** Есть
конкретные точки, где новичок упирается в стену и не понимает почему. Их
структурный аудит не ловит, а они критичнее половины «косметики» выше.

### Где новичок застрянет (по убыванию боли)

**1. Нет решений упражнений — вообще. (0 на 434 урока).** Это #1 блокер. Каждый
урок заканчивается тремя упражнениями (easy/medium/hard), и hard — это «расширь
или скомбинируй с прошлым уроком». Новичок делает его и **не может проверить,
прав ли он**. Без ментора цикл обучения разорван. Не нужны решения ко всем —
но к hard-упражнениям хотя бы скрытый ответ/тест/`solutions.md` радикально
меняет опыт самообучения.

**2. У 73% уроков нет «ожидаемого вывода». (только 119/434 показывают, что
должно напечататься).** Новичок запускает `main.py`, видит числа — и не знает,
правильные ли они. Код печатает (хорошо), но сравнить не с чем. Блок «вы должны
увидеть ≈ такое» в конце Build It закрывает петлю обратной связи почти бесплатно.

**3. Мина воспроизводимости. Все зависимости на `>=`, ни одного `==`, нет
локфайла, install-команды без версий** (`pip install torch torchvision` без
пинов). Курс написан под стек 2026 года. Новичок в 2027-м ставит `torch>=2.0`,
получает свежую несовместимую версию, урок падает на изменившемся API — **без
единой подсказки, что дело в версии**. Нужен либо `requirements.lock`/пины, либо
честная строка «проверено на torch 2.x, transformers 4.x» в шапке.

**4. Нет предупреждения про железо и деньги заранее. 12 уроков требуют
GPU/`cuda`, 39 дёргают платные API (anthropic/openai).** В шапке урока поля нет
(только Type/Languages/Prerequisites/Time). Новичок с ноутбуком без GPU и без
оплаченного ключа узнаёт об этом **посреди урока**. А README обещает «запуск на
вашем ноутбуке». Достаточно поля `**Requires:**` (CPU-only / GPU / платный API
~$X) в шапке — и человек планирует, а не врезается.

**5. Пререквизиты не кликабельны — 0 из 434.** Каждый урок пишет «Phase 7 · 02
(Self-Attention)» простым текстом. Новичок упёрся в незнакомый пререк — и
вместо клика идёт искать урок руками по дереву. Манифест знает все пути, ссылки
проставляются генератором тривиально. Это, наверное, самый дешёвый из крупных
фиксов.

**6. Глоссарий тонкий для своего жаргона. 83 термина на 20 доменов.** Содержит
«Agent», но не «ReAct», «MemGPT», «ReWOO», «Reflexion» — а ровно ими
intro-урок P14/01 встречает с первого абзаца. Когда новичок читает «каждый
агент — вариант ReAct-петли», глоссарий не выручает. Жаргон на входе в
*продвинутые* фазы плотный (в отличие от мягких фундаментальных интро).

**7. «Когда застрял» — почти некуда пойти.** README предлагает только
`/find-your-level` и `/check-understanding` — а они требуют AI-агента со
SkillKit. Для новичка *без* Claude/Cursor нет ни ссылки на GitHub Discussions,
ни Discord, ни FAQ/Troubleshooting. CONTRIBUTING.md — про контрибьюторов, не про
застрявшего ученика.

### Что для новичка сделано хорошо (чтобы не сломать при правках)

- **Мягкий, правильно настроенный вход** (P1/01, P12/01 — объясняют «зачем»
  прежде «как», без снобизма).
- **426/426 кода печатают результат и запускаются автономно** (`__main__`).
- **«С нуля, потом фреймворк»** — лучший из существующих способов *понять*, а не
  заучить.
- **Пререквизиты везде объявлены** (нужно только сделать их кликабельными).
- **`/find-your-level`** — хороший placement-quiz, чтобы не начинать с нуля зря.
- **Прыжки сложности зашлюзованы пререками** (P7 требует P3+P5, P10 требует P5) —
  курс не роняет новичка в глубину без предупреждения.

### Что добавить именно ради новичка

| Фикс | Цена | Эффект |
|---|---|---|
| Кликнабельные пререквизиты (из манифеста, генератором) | низкая | навигация без ручного поиска |

## Чего не хватает курсу в целом (выше уровня отдельных уроков)

1. **Решений-ориентиров (decision aids).** Курс отлично учит «как работает X»,
   но реже даёт «когда выбирать X vs Y». Где это есть (`11/17-agent-framework-
   tradeoffs`, `17/28-self-hosted-serving-selection`) — очень ценно. Стоит
   добавить такие сравнительные врезки в фазы с зоопарком методов (P8 generative
   families, P12 fusion-стратегии, P16 топологии).

2. **Связок между дублирующими темами.** Speculative decoding живёт в 7/16 →
   10/15 → 17/05 (три ракурса — это хорошо), constitutional AI ×3, ViT ×3. Но
   уроки не ссылаются друг на друга явно. Блок «Как это соотносится с уроком X»
   превратил бы случайные повторы в осознанную спираль.

3. **Единого определения «готовности» урока.** Сейчас ✅ ставится по наличию
   `code/`+`outputs/`, но Learning Objectives и диаграммы — нет. Стоит
   зафиксировать чек-лист «урок завершён» (цели + проблема + концепция + код +
   артефакт + упражнения + ≥1 визуал + кликабельные источники) и прогнать по нему
   `site/build.js --check` как мягкое предупреждение.

4. **Связи квизов с покрытием.** Квизы есть у 124/434. Раз колонка покрытия уже
   в ROADMAP — стоит сделать дозаполнение квизов отдельным треком (фазы 5,6,8,9,
   12–15,17,19 — нули).

## Принятые решения по реализации

Блокирующие выборы по форматам закрыты — будущие волны и контрибьюторы следуют им
(зафиксировано в `LESSON_TEMPLATE.md`):

| Решение | Выбор | Где живёт |
|---|---|---|
| Кликабельные пререки | render-time в `lesson.html` (не переписывание исходников — уроки по-разному маршрутизируются на GitHub и сайте) | ✅ сделано, Волна 0 |
| Поле `Requires` | 3 категории без $: **CPU-only / GPU / Paid API** (цены протухают быстрее версий) | Волна 1 |
| Решения упражнений | скрытый `<details>` под hard-упражнением, в самом уроке (0 новых файлов, двуязычно) | Волна 3 |
| Локфайл | один глобальный `requirements.lock` в корне + строка «проверено на …» в шапке | Волна 5 |

## Рекомендованный порядок работ

1. **P0-баги (полчаса):** переименовать артефакт в `06/11`, добить `outputs/` в
   `08/15` и `10/23`, заполнить пустые квизы в `11/16` и `11/17`.
2. **Дешёвые beginner-фиксы (день, огромный эффект на самообучение):**
   кликабельные пререквизиты (генератором из манифеста), поле `**Requires:**`
   (CPU/GPU/платный API) в шапке, локфайл/пины версий + строка «проверено на …»,
   секция «Когда застрял» в README.
3. **Закрыть 🚧 (несколько вечеров):** довести 5 незавершённых уроков до ✅.
4. **Learning Objectives в 8 фазах (механически, окупается сразу):** P5,6,7,8,9,
   15,16,19. Можно полу-автоматизировать с вычиткой.
5. **Петля самопроверки для новичка (по фазам):** блок «ожидаемый вывод» в Build
   It + решения/тесты к hard-упражнениям. Самый дорогой, но и самый ценный трек
   для самостоятельного ученика.
6. **Диаграммы, по приоритету:** P12 → P7 → P9 → P6 → P13. Врезки в готовый текст.
7. **Кликабельные источники:** P3 и P1 (проставить URL к классике); расширить
   глоссарий жаргоном продвинутых фаз.
8. **Чек-лист готовности** в `build.js` как warning — чтобы регресс не вернулся.

Пункты 1–2 — дни, и при этом 2 снимает большую часть беспомощности новичка.
Пункт 5 — самый трудоёмкий, но именно он превращает курс из «отличного для
чтения» в «отличный для самостоятельного прохождения». Всё остальное —
механическая, распараллеливаемая по фазам отделка готового курса, а не
достройка дыр.
